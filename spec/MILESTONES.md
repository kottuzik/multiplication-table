# MILESTONES – כפל כיף (Times Fun)

מסמך זה מגדיר אבני דרך לפיתוח בהתאם ל-`PRD.md`, ל-`ARCHITECTURE.md` ול-`DESIGN.md`. כל Milestone מסתיים בתוצר עובד וניתן לבדיקה. הסדר מחייב, ואין להוסיף יכולות שאינן מוגדרות במסמכי המקור.

## Milestone 1 – תשתית אפליקציה, מסך בית עובד ופריסה ראשונה

**מטרה:** להעמיד אפליקציית React בסיסית שניתן להפעיל בדפדפן ולהתחיל ממנה תרגול, ולפרסם אותה בכתובת ציבורית כדי שניתן יהיה לבדוק כל Milestone גם בטלפון (ראו ADR-2 ב-`ARCHITECTURE.md`).

**מה יש לממש:**
- פרויקט React + TypeScript + Vite ב-Repository הקיים (`kottuzik/multiplication-table`), מבנה פשוט לשלושת המסכים ו-CSS לפי `DESIGN.md`.
- ניווט מקומי בין בית, לימוד לוח הכפל ואודות, כולל כפתורי **בואו נתרגל**, **אודות** ו-**חזרה**, ללא React Router. כפתור "חזרה" של המכשיר/הדפדפן מחזיר ממסך משני לבית (ADR-1).
- מסך בית מעוצב לפי ה-Wireframes וה-Mockups: שם **כפל כיף**, כיתוב משנה, איור מתמטי מקומי ושני כפתורי ניווט. הטקסטים לפי טבלת הטקסטים המאושרים ב-PRD.
- מסכי יעד בסיסיים עם כותרת וחזרה לבית, כדי שהניווט כולו יהיה ניתן לבדיקה; התוכן המלא שלהם יפותח בהמשך.
- כפתור השפה (גלובוס + "English") מוצג במקומו בכל המסכים לפי `DESIGN.md`, אך עדיין ללא פעולה; ההחלפה עצמה תמומש ב-Milestone 3.
- כל טקסטי הממשק נלקחים כבר מעכשיו ממילון טקסטים מקומי (בשלב זה בעברית בלבד), כדי שב-Milestone 3 יתווסף רק התרגום לאנגלית, בלי לשכתב את המסכים.
- GitHub Actions Workflow שמריץ `npm ci`, בדיקות ו-`npm run build`, ומפרסם את `dist` ל-GitHub Pages בעקבות Push ל-`main`, עם `base: '/multiplication-table/'`.

**תוצר מצופה:** אפליקציה שנפתחת במסך הבית ומאפשרת מעבר לכל אחד משני המסכים האחרים וחזרה, מקומית ובכתובת GitHub Pages.

**Definition of Done:**
- `npm run build` מסתיים בהצלחה והאפליקציה נפתחת ללא שגיאות Runtime.
- שלושת יעדי הניווט קיימים; הכפתורים מובילים למסך הנכון ו-**חזרה** מחזיר לבית.
- כפתור "חזרה" של הדפדפן/המכשיר במסך לימוד או אודות מחזיר לבית ואינו יוצא מהאפליקציה.
- מסך הבית תואם את המבנה והכיוון RTL של ה-Wireframes ואת הצבעים, הפונט והסגנון של `DESIGN.md`.
- האיור הוא קובץ SVG מקומי שנוצר לפרויקט בסגנון ה-Style Guide; שם האפליקציה מוצג כטקסט (ללא לוגו גרפי).
- הגופן Rubik נטען מקבצים מקומיים בתוך הפרויקט, ללא פנייה ל-Google Fonts או לשירות חיצוני.
- חצי הכפתורים בכיוון העברית: **חזרה** מצביע ימינה, כפתורי המעבר מצביעים שמאלה.
- הממשק שמיש בנייד ואינו יוצר גלילה אופקית.
- קובץ ה-Workflow קיים ותקין. הפרסום בפועל מתבצע רק לאחר שהמשתמש מאשר Push ומפעיל את GitHub Pages בהגדרות ה-Repository (בהדרכה); לאחר מכן הכתובת `https://kottuzik.github.io/multiplication-table/` נפתחת ומציגה את מסך הבית ללא שגיאות 404.

## Milestone 2 – תרגול לוח הכפל מקצה לקצה

**מטרה:** לאפשר לילד לבחור טבלה, לפתור תרגילים ולקבל משוב מיידי ומונה תשובות נכונות.

**מה יש לממש:**
- מסך לימוד מעוצב: בורר **הכול** / 1–10 בשתי שורות (לפי `DESIGN.md`), תרגיל, שדה תשובה, כפתור **בדיקה**, אזור משוב ומונה **תשובות נכונות**.
- מנוע תרגילים מקומי: גורמים בטווח 1–10; במצב **הכול** שני גורמים אקראיים; בטבלה N אחד הגורמים הוא N; חזרות מותרות.
- קלט מספרי של עד שלוש ספרות, מקלדת מספרית בנייד, סינון תווים לא תקינים גם בהדבקה וטיפול בשדה ריק.
- תשובה נכונה: הודעת **נכון! כל הכבוד!**, הגדלת המונה פעם אחת והצגת תרגיל חדש. תשובה שגויה: **לא נכון, נסו שוב**, ניקוי הקלט והותרת התרגיל והמונה ללא שינוי.
- החלפת טבלה מציגה תרגיל חדש, מאפסת את הקלט והמשוב אך שומרת את המונה. מצב התרגול נשמר בזיכרון בלבד, ללא Persistence.
- מעבר למסך אחר וחזרה ללימוד שומר את המונה, הטבלה והתרגיל (הקלט והמשוב מתנקים).
- כפתור **דלג**, רשימת דילוגים בסשן, כפתור **סיום תרגול** וחלון סיכום בתוך מסך הלימוד עם התרגילים שנשארו ללא פתרון ותשובותיהם, לפי ה-PRD וה-`DESIGN.md`.
- אחרי כל בדיקה הסמן חוזר לשדה התשובה; הודעת המשוב מוצגת מתחת לכפתור **בדיקה**, נשארת עד ההקלדה הבאה, וטקסט ההודעה בצבע כהה עם אייקון ✓/✗ ורקע ירוק/אדום לפי `DESIGN.md`.

**תוצר מצופה:** מסך תרגול מלא ועובד, שניתן להשתמש בו ברציפות ללא שירות חיצוני.

**Definition of Done:**
- בדיקות Vitest מאמתות את טווחי התרגילים, מצב **הכול**, טבלה נבחרת, תשובה נכונה/שגויה והחלפת טבלה.
- בדיקות UI מאמתות קלט ריק, תווים לא מספריים, אורך מקסימלי, ניסיונות חוזרים ומניעת ספירה כפולה בלחיצה מהירה.
- תשובה נכונה מגדילה את המונה בדיוק ב-1; תשובה שגויה אינה מגדילה אותו ואינה מחליפה תרגיל.
- החלפת טבלה אינה מאפסת את המונה; טעינה מחדש מאפסת אותו. לא נשמרים נתוני תרגול ב-Storage.
- מסך הלימוד תואם את רכיבי ה-UI והפריסה ב-`DESIGN.md`, לרבות תוויות, Focus ומשוב טקסטואלי נגיש.
- מעבר לבית או לאודות וחזרה ללימוד שומר את המונה, הטבלה והתרגיל.
- בורר הטבלאות מוצג בשתי שורות, כל כפתור לפחות 44×44 פיקסלים, ללא גלילה אופקית ברוחב 320 פיקסלים ומעלה.
- אחרי לחיצה על **בדיקה** ה-Focus חוזר לשדה התשובה; הודעת המשוב גלויה מתחת לכפתור ונעלמת עם ההקלדה הבאה.
- דילוג מציג תרגיל חדש, אינו משנה את המונה ומוסיף את התרגיל לרשימה פעם אחת בלבד; פתרון נכון מאוחר של תרגיל שדולג מסיר אותו מהרשימה (נבדק ב-Vitest).
- **סיום תרגול** פותח חלון עם התרגילים שנשארו ללא פתרון ותשובות נכונות, או הודעה מעודדת כשאין כאלה; **סגירה** מחזירה לתרגול בלי לשנות מונה, רשימה, טבלה או תרגיל. החלון נגיש במקלדת ובקורא מסך.

## Milestone 3 – מסך אודות וממשק דו-לשוני מלא

**מטרה:** להשלים את שלושת המסכים ולאפשר שימוש עקבי בעברית ובאנגלית.

**מה יש לממש:**
- מסך אודות מעוצב ובו הסבר קצר וטבלת כפל מלאה 10×10 כרכיב HTML Table עם כותרות שורות ועמודות.
- מילוני טקסט מקומיים בעברית ובאנגלית לכל שלושת המסכים, כולל הודעות תרגול, תוויות וכפתורים.
- הפעלת כפתור השפה בכל מסך (כפתור יחיד שמציג את השפה השנייה), החלפה מיידית של `lang` ו-`dir` ברמת המסמך, והתאמת RTL/LTR, יישור וחצים.
- ברירת מחדל לפי שפת הדפדפן: אנגלית כשהשפה הראשית היא אנגלית, ועברית אחרת; שמירת בחירה ידנית של שפה בלבד ב-`localStorage`, בהתאם להחלטה המופיעה ב-PRD ובארכיטקטורה.
- כל הטקסטים בשתי השפות לפי טבלת הטקסטים המאושרים ב-PRD.

**תוצר מצופה:** שלושת המסכים גמורים, עם מעבר בין שפות ללא פגיעה במצב התרגול.

**Definition of Done:**
- טבלת הכפל כוללת 100 תוצאות נכונות, כותרות שורה ועמודה וקריאות גם במסך צר, ללא גלילה אופקית של העמוד. הטבלה מוצגת משמאל לימין בשתי השפות.
- החצים בכפתורים מתהפכים בהחלפת שפה (באנגלית **Back** מצביע שמאלה).
- כל טקסטי הממשק משתנים לעברית/אנגלית; אין מחרוזות ממשק שנותרו בשפה הלא נכונה.
- החלפת שפה באמצע תרגיל שומרת את התרגיל, הקלט והמונה.
- `lang` ו-`dir` מתעדכנים כראוי, והתרגיל המתמטי מוצג בסדר קריא בשני הכיוונים.
- בחירת שפה ידנית נשמרת בטעינה מחדש; כאשר `localStorage` חסום, האפליקציה ממשיכה לפעול.
- שלושת המסכים תואמים את מבנה ה-Wireframes ואת העיצוב שב-Style Guide וב-Mockups.

## Milestone 4 – PWA, התקנה ושימוש Offline

**מטרה:** להפוך את האפליקציה ל-PWA שניתן להתקין ולהפעיל ללא אינטרנט לאחר טעינה ראשונה מוצלחת.

**מה יש לממש:**
- `vite-plugin-pwa` עם Workbox במצב `generateSW`, Web App Manifest, אייקונים מקומיים ו-Service Worker.
- Precache של App Shell, קובצי JS/CSS, פונטים, איורים, אייקונים וכל הנכסים החיוניים.
- התאמת נתיבי `base`, `start_url` ו-`scope` לנתיב ה-Repository ב-GitHub Pages.
- מדיניות עדכון לפי ADR-3: גרסה חדשה נכנסת לתוקף בפתיחה הבאה בלבד, ללא הודעה וללא רענון כפוי.
- אייקוני האפליקציה נגזרים מאיור הבית, כולל אייקון ייעודי לאייפון (`apple-touch-icon`). השם מתחת לאייקון: **כפל כיף**. ללא מסכי פתיחה ייעודיים לאייפון.

**תוצר מצופה:** Build שניתן להתקין כ-PWA ולהשתמש בכל שלושת מסכיו Offline לאחר השלמת טעינה ו-Cache ראשוניים.

**Definition of Done:**
- ה-Build כולל Manifest תקין ו-Service Worker שנרשם ופועל ב-HTTPS או ב-Localhost.
- לאחר התקנה, השם מתחת לאייקון הוא **כפל כיף**, ובאייפון מוצג האייקון הייעודי (לא צילום מסך של הדף).
- לאחר טעינה מקוונת ראשונה והשלמת Precache, ניתוק הרשת ופתיחה מחדש מאפשרים ניווט, תרגול, החלפת שפה וצפייה בטבלה ובאיור ללא שגיאות רשת (נבדק על ידי ה-AI בדפדפן במחשב).
- האייקונים והנכסים המקומיים זמינים Offline; אין תלות ב-CDN או ב-API בזמן שימוש.
- **בדיקה ידנית של המשתמש** בכתובת GitHub Pages (לאחר Push מאושר): התקנה ושימוש Offline ב-Chrome Android וב-Safari iOS. ה-AI מספק הוראות בדיקה צעד אחר צעד ומתעד את התוצאות ואת מגבלות ההתקנה הספציפיות למכשיר.
- עדכון גרסה אינו מוחק סשן פעיל באמצעות Reload כפוי.

## Milestone 5 – בדיקות קבלה של הגרסה המפורסמת

**מטרה:** לאמת שהמוצר השלם, שכבר מתפרסם אוטומטית מאז Milestone 1, שמיש, עקבי ויציב בכתובת הציבורית.

**מה יש לממש:**
- אימות שה-Workflow (שהוקם ב-Milestone 1) עדיין מריץ בדיקות ו-Build ומפרסם כל Push ל-`main`; תיקון במידת הצורך.
- אימות נתיבים יחסיים, HTTPS וטעינת כל הנכסים בכתובת הפרויקט.
- בדיקות קבלה בנייד ובדסקטופ: ניווט, תרגול, שפות, RTL/LTR, תצוגה רספונסיבית, נגישות בסיסית, התקנה ו-Offline. בדיקות הנייד מבוצעות על ידי המשתמש לפי הוראות צעד אחר צעד שה-AI מספק.

**תוצר מצופה:** אפליקציית כפל כיף פעילה בכתובת GitHub Pages, עם Deployment אוטומטי לאחר שינויי קוד שעברו בדיקות.

**Definition of Done:**
- Workflow מצליח ומפרסם את ה-Build ללא פעולת פריסה ידנית בכל עדכון.
- כתובת ה-HTTPS הציבורית נפתחת; שלושת המסכים וכל הנכסים נטענים ללא שגיאות 404.
- זרימת משתמש מלאה נבדקה: בית → לימוד → פתרון נכון ושגוי → בחירת טבלה → חזרה → אודות → חזרה.
- החלפת שפה, שמירת העדפת השפה ואיפוס מונה בטעינה מחדש עובדים בגרסה המפורסמת.
- האפליקציה שמישה במסכים צרים, עם כפתורים נגישים, תוויות, Focus ברור ומשוב שאינו מבוסס על צבע בלבד.
- לאחר ביקור מקוון ראשון והשלמת Cache, הגרסה המפורסמת פועלת Offline בהתאם ל-PRD.
- אין Backend, Database, חשבונות, Analytics או שירותי Cloud נוספים מעבר ל-Hosting הסטטי שנבחר.

## Development Execution Rules – הוראות מחייבות ל-AI המבצע

1. יש לפתח את ה-Milestones **לפי הסדר** המוגדר במסמך; אין לדלג על Milestone או להתחיל Milestone מתקדם לפני השלמת קודמו.
2. בתום **כל Milestone**, יש **לעצור את הפיתוח** ולהציג למשתמש את התוצר העובד, מה מומש ותוצאות הבדיקות בפועל מול כל סעיף ב-**Definition of Done**. יש לציין במפורש בדיקות שלא בוצעו או תנאים שלא הושלמו; אין לדווח על הצלחה ללא בדיקה.
3. **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש.** אישור טכני אוטומטי או מעבר שקט לשלב הבא אינם מספקים.
4. בכל Milestone יש לשמור על ההתאמה ל-`PRD.md`, ל-`ARCHITECTURE.md` ול-`DESIGN.md`, בלי להוסיף פיצ'רים או שירותים שלא אושרו.

**הערת תשתית:** הארכיטקטורה היא Static PWA ללא Database או Supabase. לכן אין צורך בסביבות Database נפרדות או ב-Database Migrations.
